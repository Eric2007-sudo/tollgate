# 模型分档：把「贵模型」留给真正贵的地方

## 为什么这一步能省钱，而且省得比压缩上下文多

一次长会话里，输入 token 的绝大部分是**重复喂的上下文**，只有很小一部分是「需要深想」的信号。
用同一个模型处理全部内容，等于让最贵的模型去干「找文件在哪」「跑一遍测试」「把 JSON 转成表格」这些不需要推理的活。

分档的本质：**把推理密度低的步骤交给便宜模型，把推理密度高的步骤交给贵模型。**

按官方 DeepSeek 定价（2026-10 核实，闲时 / 高峰，单位 ¥/百万 token）：

| 模型 | 缓存命中 | 输入 | 输出 |
|---|---|---|---|
| `deepseek-v4.1-flash` 闲时 | 0.02 | 1 | 4 |
| `deepseek-v4.1-flash` 高峰 | 0.04 | 2 | 8 |
| `deepseek-v4-pro` 闲时 | 0.15 | 4.5 | 13.5 |
| `deepseek-v4-pro` 高峰 | 0.3 | 9 | 27 |

flash 与 pro 的输入价差 **4.5 倍**，输出价差 **3.4 倍**。
一步 12k 输入的 `std` 步骤丢给 `deep` 跑，多花的钱相当于把前后 5 个 `cheap` 步骤变成了白送。

## 三个档位的判据

判断标准不是「任务重要不重要」，而是**「这一步失败一次，代价有多大」+「这一步需要跨多少文件推理」**。

### `cheap` — 侦察、机械操作

**特征**：目标明确、输出可验证、失败可重来、不需要跨文件权衡。

典型步骤：
- 用 `grep` / `rg` 定位符号在哪些文件里
- 读一个文件并总结它的导出接口
- 跑测试、跑类型检查、跑格式化、看报错
- 把上一个步骤的结论整理成 notes
- 单文件的小改（改常量、加日志、改一个分支条件）
- 按已有模板生成样板代码

### `std` — 常规实现

**特征**：需要同时看 2~4 个文件，要在既有约定内做选择，但选择空间不大。

典型步骤：
- 多文件联动改动（加一个字段，从 model 改到 API 再到前端）
- 写一个新模块的实现（结构已定）
- 写测试
- 修一个已经定位清楚的 bug
- 写脚本做一次性数据迁移

### `deep` — 决策与一次性大改

**特征**：错的代价高，或者要一次改对很多处，或者需要跨模块权衡。

典型步骤：
- 架构选型、方案取舍（\"用 JWT 还是 session\"）
- 找出复杂 bug 的根因（现象不明、跨多层）
- 一次重构涉及 10+ 文件的一致性改动
- 设计对外的接口契约 / 数据模型
- 红队 review：让强模型专门找漏洞

## 硬规则：`deep` 之前必须有 `cheap` 产出事实

**禁止**让 `deep` 步骤自己去翻文件。它应该拿到一份 `cheap` 步骤写好的事实清单，只做判断。

```
错：#3  用 deep 模型
       "读一下 auth 目录，找出所有 session 的落点，然后设计 JWT 方案"

对：#1  用 cheap 模型
       "grep 出 session 的所有落点，写进 notes/01-recon.md"
   #3  用 deep 模型
       "读 notes/01-recon.md（只有 800 token），设计 JWT 迁移方案"
```

差别：错误写法让贵模型读 30 个文件、烧 200k 输入 token；正确写法让它读 800 token。
**这一条单独的收益，通常超过所有压缩技巧的总和。**

## 各家的模型 ID 怎么对应

`--tier` 只是标签，实际路由要你在会话里做。下面是常见映射：

### OpenCode + 官方 DeepSeek

| tier | 模型 ID |
|---|---|
| `cheap` | `deepseek/deepseek-flash` |
| `std` | `deepseek/deepseek-pro` |
| `deep` | `deepseek/deepseek-pro`（配合闲时执行） |

### OpenCode + 第三方中转（如本机 `kouxian`）

| tier | 模型 ID |
|---|---|
| `cheap` | `kouxian/deepseek-v4.1-flash` |
| `std` | `kouxian/deepseek-v4-pro` |
| `deep` | 切回官方 `deepseek/deepseek-pro` |

**理由**：中转适合廉价试验与粗加工，`deep` 步骤是要进主链路的判断，走官方更稳。

切档方式（OpenCode）：

```bash
/models                      # TUI 里切当前会话
opencode run --model kouxian/deepseek-v4.1-flash "只回复：ok"   # 脚本里指定
```

子 agent 可以单独挂便宜模型（如 explore 类子 agent），这是最省的做法：**让贵模型只做决策，把检索全部外包给便宜子 agent。**

## 闲时是一个免费的 50% 折扣

官方 DeepSeek 闲时（北京时间 22:30–08:30，以及周末）价格是高峰的一半：

- `cheap` / `std` 步骤 → 攒到闲时批跑
- `deep` 步骤 → 尽量放闲时，单次省一半

用 `tg status` 看到还有一堆 `todo` 时，先问一句「这些能不能等到晚上跑」。

## 常见错配

| 症状 | 说明 | 修正 |
|---|---|---|
| 计划里 8 步全是 `deep` | 等于没分档，还贵 4.5 倍 | 把侦察类步骤降成 `cheap` |
| 计划里全是 `cheap` | 决策质量会崩，返工更贵 | 至少 1 个 `deep` 做方案把关 |
| `deep` 步骤预算 200k | 说明它被当成了搜索引擎 | 拆出侦察步骤 |
| `cheap` 步骤预算 60k | 说明它在做本该 `std` 做的实现 | 升档，或拆步骤 |
| `tier` 写了但从不切模型 | 标签纯装饰 | 在 `start` 时按 tier 切 `/models` |

预算和档位是互相校验的：**预算异常大，往往说明档位错了，或者步骤没切细。**
`tg drift` 会帮你把超预算 50% 以上的步骤点出来。
