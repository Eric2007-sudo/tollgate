# tollgate · 过闸

> 给 agent 的每一轮请求装两道闸：**这轮该不该发**，和**这轮塞多少**。
> 零依赖、单文件 CLI + 本地只读工作台。Python 3.8+，只用标准库。

```
                        ┌──────────────────────────────┐
    用户任务 ──────────▶ │  闸一 · 计划预算              │
                        │  tg init / add / start        │
                        │  gate / done / handoff        │
                        │  「该不该做、谁来做、几轮」    │
                        └──────────────┬───────────────┘
                                       │ 放行
                                       ▼
                        ┌──────────────────────────────┐
                        │  闸二 · 上下文预算            │
                        │  tg ctx / price               │
                        │  「多大、多少钱、还撑几轮」    │
                        └──────────────┬───────────────┘
                                       │ 快满了
                                       ▼
                              tg handoff N  →  换干净会话
```

---

## 为什么要有第二个闸

关于省 token，市面上主流答案是"压缩提示词"。但把这个账算清楚会发现问题不在那儿：

| 手段 | 省的是什么 | 省多少 |
|---|---|---|
| 压缩输入 | 未命中的输入 token | 一次请求的 ~2/3 输入费，**每轮都要重付一次压缩调用** |
| 少写一半代码 | 账单的**分母** | 分子再省也只有 0~13% |
| 换一个干净会话 | 输入侧几乎全部 | 一次性打到 ~600 tok 的简报 |
| 干脆不做这件事 | 100% | —— |

所以顺序必须是：**该不该做 → 谁来做 → 怎么压**。前两件事没做，压缩最多救 13%。

tollgate 就是把这个顺序做成工具：闸一管前两件事，闸二管第三件事，并且**用同一条价格口径把"压缩"和"换会话"放在一起比价**。

## 它糅合了谁的想法

这个项目的每一块机制都不是原创，来源写在下面。**改动**一列是我们实际改掉的部分——不改就只是抄袭，改错了就是自嗨。

| tollgate 里的机制 | 来自 | 改动 |
|---|---|---|
| 计划落盘成文件 + 完成由断言判定 | `planning-with-files` | 断言必须是 shell 真命令，`exit code` 说话；模型自述不算 |
| 依赖图 / 并行批次 / 产物冲突检测 | `ccpm` | 加了"两个步骤写同一个产出物"的冲突检测 |
| 自足式简报（给最弱执行者） | `shadcn/improve` | 简报 ≤600 tok，含禁区、验收命令、停止条件 |
| 同一步重试到上限强制熔断 | `LazyCodex $ulw-loop` | 熔断后必须 `reset n --rounds` 显式重开 |
| 复用七级梯子（最省钱是不做） | `Ponytail` | 梯子档位进计划文件，`report` 统计复用率 |
| 输出侧压缩 | `caveman` | **没抄压缩器**，抄的是"先问这笔压缩值多少钱" |
| 上下文压缩 | `headroom` | 改成与 handoff 的比价：结论是换手恒优 1.5× |
| 按需检索而非全量读 | `codebase-memory-mcp` | 落成计划里的禁读清单 `--exclude` + 产出物声明 |
| 本地只读看板 | `claude-mem` 的 work-view | 用标准库 `http.server` 重写，零依赖、只绑 127.0.0.1、校验 Host 头 |
| 模型档位标签 / 路由 | `claude-code-router` / `laya` | **只保留 `--tier` 标签**，不接管路由——实际路由靠会话内切模型，少一层可坏的中间件 |
| usage 记账与 `cost` | OpenCode 自身 | 不另建账本，直接读宿主的 `session_v2` / `session_message` |
| 轮数口径而不是 token 口径 | 本项目实测踩坑 | 实测 token 预算差 74 倍，于是 `--rounds` 定预算、`--budget` 只当探测器 |

## 快速开始

```bash
git clone <this repo> && cd tollgate
python tg.py price            # 先看看宿主的价目对不对得上
python tg.py ctx              # 这一轮多大、多少钱、还能撑几轮
python tg.py init "把 pipeline.py 拆成可测模块" --why "现在改一处要跑全量"
python tg.py add --title "抽出 io 层" --out "src/io.py" --budget 30000 --rounds 3 \
                 --accept "pytest::test_io"
python tg.py serve            # 打开 http://127.0.0.1:7717/
```

干完一步就 `python tg.py sync` —— 宿主跑掉多少轮、多少 token、多少钱，自动记进账本。
装成 skill：

```powershell
.\install.ps1                              # → ~/.config/opencode/skills/tollgate
.\install.ps1 -Target project -ProjectPath "D:\proj"
```

`.plan/` 目录与 `schema 2` 与上游 `plan-ledger` **完全兼容**：老计划用 `tg` 直接读，`tg` 建的计划 `pl.py` 也读得动。

## 账不用手记：`tg sync`

闸一原先要人肉记账（`tg spend 3 --in 12000 --out 900 --reqs 2`），可闸二已经能把每一轮的
`tokens` 和 `cost` 从 `session_message` 里读出来了。中间那道缝不该让人去补：

```bash
python tg.py start 2
# ...干活，让 agent 跑几轮...
python tg.py sync                 # 自动把「上次 sync 之后的新轮次」记进 #2
python tg.py sync --dry-run       # 只报数，不写账本、不动游标
```

口径和 `spend` **完全一致**，不另立一套：

| 账本字段 | 取什么 | 为什么 |
|---|---|---|
| `in` | Σ 每轮 `tokens.input` | 新输入；缓存命中不计入 |
| `out` | Σ(`output` + `reasoning`) | 推理 token 按输出价计费，属于新 token |
| `reqs` | 轮数 = 带 tokens 的 assistant 消息条数 | 轮数才是靠谱的预算单位 |
| `cost` | Σ 每轮真实 `cost`；宿主没记就按配置单价重算并标 `cost_est` | 有真账就用真账 |
| `cache_read` / `cache_write` | 单列存进记录，**不参与预算求和** | 命中只是便宜的重读，混进预算会让"该压还是该换手"判断失真 |

游标存在 `.plan/sync.json`，**每个会话各存一份**（schema v2：`sessions: {会话id: ids}`），所以：

- 同一轮**永远不会重复记账**，多跑几次 `sync` 是安全的；
- 换会话不会吃掉别的会话的轮次，**回来也不会重记**（老的 v1 单游标文件读的时候自动升上来）；
- 游标文件坏了就当从没同步过，从头重算，不崩。

这条是踩出来的：以前只有一份游标、换会话就清空，于是「对 A 记完 → 去 B 记一遍 → 回来对 A」
把 A 整段重记了一遍——实测应有的 4 轮 / \$0.0011 被记成 7 轮 / \$0.0014。会话不是一根计数
器，是几根并行的计数器。

三个诚实的边界：**归账只能归到"正在做"的那一步**（宿主不知道你的步骤边界，所以切步骤
前先 `sync` 一次是你的事）；**读窗口是最新 2000 轮**，更早的读不到也就不计入，这时输出
会明说，别把那次的 tok 数当成"会话总共跑了多少"（那看 `tg ctx`）；**一次 `sync` 只认一个
会话**，所以账本记的钱是**下限** —— 同期在别处跑的子 agent、另一个窗口、切回官方之前那个
会话，它们的花费都不在里面。这种情况 `sync` 会主动说出来，不等你自己发现：

```text
  钱：$0.373855（¥2.5008） · 宿主记录
  另有 4 个会话同期也在花钱（合计 $38.807691）—— 它们还没入账：要入账就逐个 tg sync --session <id>（每个会话各有游标，来回切不会重记）。
```

上面这行是真实输出：那 4 个会话加起来比这次对账的 $0.37 大两个数量级。要分摊账单，
这个差不能装作不存在。**补账不会翻倍**——逐个 `sync --session <会话id>` 就行，
每个会话各有一份游标，来回切多少次都只记一次。

记完账，`tg report` 的「钱」那一栏才有真数（`spend` 只记 token，记不到钱）；没有 `cost`
的账本会明说"账本里没有 cost"，不会拿 token 数硬折成钱。`tg done` 也会在收尾时拉你一把：
宿主就在本机、这步却没对过账，它会提醒先 `sync` 再标记完成。

## 数据从哪来，钱怎么算

| 数据 | 来源 | 口径 |
|---|---|---|
| 逐轮上下文 | `session_message.data` 的 `tokens` | `input + cache.read` = 这一轮真正送进模型的量 |
| 逐轮花费 | 同一行的 `cost` | 宿主自己算的，优先采信 |
| 账本记账 | `tg sync` 从上面两行推导 | `in`=Σinput，`out`=Σ(output+reasoning)，`cache_read` 单列不入预算 |
| 会话累计 | `session_v2` | 只用于"会话级命中率"，**绝不冒充单轮值** |
| 价格表 | `opencode.json` 各 provider 的 `cost` | USD / 百万 token |
| 窗口 | 模型 `limit.context` | 中转若虚标就对不上，会在 `ctx` 里显形 |

计费公式与 OpenCode 一致（实测逐位对账过）：

```
usd = (input×p_in + (output + reasoning)×p_out + cache_read×p_cr + cache_write×p_cw) / 1e6
```

**推理 token 按输出价计**——漏掉这一项就对不上账。

## 本地工作台

`tg serve` 起一个只绑 `127.0.0.1` 的只读看板（校验 Host 头，防 DNS rebinding），一屏看到：

- 计划进度条、每步预算 vs 已用、轮数是否超预算、**每步的真实花费**
- **账本花费**：只认账本里宿主记过的 `cost`；一笔都没有时显示「没有」，不拿 token 折算
- **同期在花**：另有几个会话在计划建立之后也花了钱（`other_sessions` / `other_usd`）。
  有这笔才出现，因为**账本只记一个会话，所以看板上的钱也是下限**
- **对账状态**：上次对账时间 + 这 40 轮窗口里还有几轮没入账（`pending_in_window`）
- 本轮上下文占窗口的比例（过半变黄，八成变红）
- **按近 8 轮中位增速，还有几轮撞到 90% 窗口**
- 最近 16 轮的上下文柱状趋势（悬停显示每轮花费与命中率）
- 判断清单：这一轮该 handoff、该修前缀、还是该继续

「账本花费」是**上次 `sync` 那一刻**的快照，宿主累计（`ctx.cumulative`）一直在涨——两者差多少
≈ 上次对账之后又跑掉的钱。看板把「截至上次 sync」写在卡片上，不假装自己实时。

它是一个静态页 + 一个 JSON 接口，没有构建步骤，没有前端依赖。

要写脚本读 `/api/state`，用 `http.client` 直连。用 `urllib` 时如果本机设了 `HTTP_PROXY`，
请求会被代理吞掉（返回 502 而不是看板的 200）——这不是服务的问题，域名白名单加上 `127.0.0.1` 就行。

## 实测样本

在真实长会话上跑出来的样子（128k 窗口、中转 `deepseek-v4.1-flash`）：

```
某一轮上下文 74.7k tok（窗口 128k 的 58%）
构成 input 227 + cache_read 74.5k，本轮命中率 99.7%
近 8 轮中位增速 +711 tok/轮 → 距窗口 90% 还有 56 轮
这一轮 $0.000316（¥0.0021）（消息自带 cost）
```

含义很直接：**还没到要换手的时候，但按当前增速五十几轮后会到。** 这种"提前几十轮就知道"的信息，是压缩提示词给不了的。

`tg sync` 在同一个宿主的另一个长会话上跑出的对账（714 轮，真实 `session_message` 逐轮数据）：

```
本次同步 714 轮
新输入 2384.8k + 输出 360.5k（其中推理 215k）= 2960.3k tok
缓存读 45495.4k / 写 0 —— 不计入预算
钱：$0.276054（¥1.8466） · 宿主记录
```

两件事值得注意：**缓存读是新输入的 19 倍**——这个会话的账几乎全落在"重读已有上下文"上，
所以省钱的着力点不是少写两行新输入，而是**让每轮要重读的前缀变短**（压缩），或者干脆
**换个短前缀**（handoff）；**推理 token 占输出的 60%**——记账时漏掉它，钱就对不上。

完整输出见 `examples/example-sync.txt`。

## 局限（诚实清单）

1. 只认 OpenCode 的 sqlite 布局；其它宿主需用 `TOLLGATE_DB` 提供同构库。
2. 逐轮数据依赖宿主把 `tokens` 写进消息行；没有就退回采样差值，再没有就报"未知"——**不编数**。
3. 窗口大小取自配置的 `limit.context`，中转虚标就会算错占比。
4. `cost` 值是**上界**：中转的分组倍率通常还会打折。
5. 压缩比固定按 3:1 估，不实测（要用实测得先有压缩器，本项目不做压缩器）。
6. 增速用中位数，遇到"这轮突然读了个大文件"会滞后一轮才反映。
7. 不接管模型路由：`--tier` 只是标签，真路由靠会话内切模型。
8. 看板只读 + 采样，**不能从 UI 改计划**——写操作只走 CLI，才有 append-only 留痕。
9. `.plan/` 与 schema 2 与上游 `plan-ledger` 共享，改格式会同时影响两者。
10. `sync` 的归账是**按"谁在 doing"归的**：上次 sync 之后的所有轮次都算到当前那一步上。
    宿主不知道你的步骤边界，所以**切步骤之前先 sync 一次**是你的事，不是工具的事。
11. `sync` 读窗口是最新 2000 轮。更早的读不到，也就不计入；遇到超长会话时输出会明说，
    别把那次结果当成"会话总共花了多少"（那看 `tg ctx` 的会话累计）。
12. `sync` 只认带 `tokens` 的 assistant 消息。一轮里如果宿主没写 tokens，那轮就是漏记的，
    账本只保证"与宿主记到的一致"，不保证"与真金白银一致"。
13. `ctx` 只看最近 40 轮（`CTX_WINDOW`）。会话比这长时它**不说"第 N 轮"**——那个 N 只是
    窗口大小，不是轮次序号；谎报轮次比不报更坏。
14. `sync` 一次只认**一个**会话，所以账本里的钱是**下限**。同期在别处跑的花费（子 agent、
    另一个窗口、切回官方那个会话）不会自己进账本；`sync` 会点名报出它们合计多少，但要**你**
    决定要不要逐个 `tg sync --session <id>` 补账——它不替你判断哪个会话算这个任务的账。
15. 游标按会话分开存（`sync.json` v2），最多记 32 个会话、每个会话最近 2000 条 id。超了就按
    「最近同步」淘汰最久没动过的那个——被淘汰的会话下次再 `sync` 会整段重记。单个长会话的
    游标很大：1020 条 id ≈ 39 KB。
16. `plan.json` / `ledger.jsonl` 认 BOM（Windows 编辑器会加），但**只认 BOM**：手改 JSON 时
    结构写错、字段拼错，工具不会猜你的意思，该报错就报错。

## 设计约束（四条，不破）

1. **零依赖** 只用标准库，Windows / macOS / Linux 同一份代码
2. **单一真相** `.plan/plan.json` 是唯一真源，`.plan/plan.md` 只是渲染视图
3. **追加写** `ledger.jsonl` / `ctx.jsonl` 只 append 永不改写，崩溃可恢复
4. **确定性门禁** 「完成」由断言 `exit code` 决定，不由模型自述决定
